# 文件使用指南

## 新项目怎么用

把**新项目路径**和已手动完成的需求澄清、技术选型、PRD 与验收标准、原型文件交给开发助手。助手先检查项目已有文件，再把本目录的 `AGENTS.md`、`README.md` 和整个 `docs` 文件夹按原结构合并到项目根目录；同名文件不直接覆盖。项目内需要填写的路径、状态和实际命令由助手核对后填写，不要求你手工逐项填写。

## 每个文件做什么

| 文件 | 用途 | 何时使用 |
| --- | --- | --- |
| `README.md` | 整体流程、停止点和可复制的独立审查指令 | 接入时阅读；通常不用按项目改写 |
| `AGENTS.md` | 开发助手必须遵守的架构确认、任务执行、验证、审查和换窗口恢复规则 | 接入时与项目已有规则合并；每次任务开始前读取 |
| `docs/README.md` | 四份输入资料的实际路径、架构确认状态、当前阶段和下一步 | 接入时填写；关键进展或换窗口前更新 |
| `docs/architecture/_template.md` | 架构方案格式：系统边界、模块、数据/API 契约、风险和基础架构验收 | 架构设计时复制为项目架构文档，提交具体版本供你确认 |
| `docs/specs/_template.md` | 一个工作包的任务、验收结果、独立审查和恢复记录 | 架构通过后先用于基础架构工作包；之后按开发计划用于功能工作包 |
| `docs/plans/_template.md` | 大阶段 → 工作包 → 小任务的拆分、依赖、验收覆盖和阶段停止点 | 基础架构通过验证与独立审查后，复制为项目开发计划 |
| `docs/development.md` | 项目真实可运行的启动、测试、构建命令和环境前提 | 搭建或核对基础架构时填写；命令变化时更新 |
| `docs/testing-mode.md` | 何时做局部测试、阶段集成、慢测和失败复验 | 基础架构及后续开发时使用；通常不用改 |

`_template.md` 是空白模板；复制为项目实际文档后再填写。项目已有等效的架构、计划、spec 或开发指南时，沿用原文件并补齐必要内容，避免维护两份相同记录。

## 执行顺序

1. **你手动完成**需求澄清、技术选型、PRD 与验收标准、原型设计；助手核对文件及现有代码，不重做这些设计。
2. **助手设计架构**，交付带版本的方案。**你明确回复该版本“通过”之前，助手停止基础架构代码搭建和功能开发。**
3. **助手搭建或核对前后端基础架构**，按获批架构验证并进行独立审查；已有合格基架无需重建。
4. **助手拆分开发任务**：从 PRD 验收项、原型、获批架构和实际基架形成大阶段、工作包、小任务，写明依赖、验收方式和停止点。
5. **助手按依赖开发**，每项任务记录实际验证并交独立窗口或独立审查人检查。换窗口先核对代码和证据，再从记录的下一步继续。

架构确认是明确的人工检查点；已批准范围内的小任务不要求你逐项重复确认。新增业务取舍、架构变化、费用或不可逆风险仍由你决定。找不到的资料写“未提供”，未执行的验证写“未验证”。本模板不会自动运行，也不生成 `.ai-dev`；独立窗口能否自动开启，要在具体开发软件中实际验证。
