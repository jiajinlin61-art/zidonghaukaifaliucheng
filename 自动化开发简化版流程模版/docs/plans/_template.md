## 拆分方法与覆盖核对

1. 按用户可验收的能力和必要依赖划分大阶段（Phase），给每阶段写目标、入口、出口验收与停止点；项目规模小可只有一个阶段，不空造层级。
2. 每阶段按能独立交付或集成的功能划分工作包（Work package）；一个工作包对应一份现有或新建 spec。
3. 每个工作包拆成有明确输入、输出、验收方式和依赖的小任务（Task）；不按文件数或每次编辑拆任务。把跨端联调、迁移、真实集成、阶段验收作为明确任务或验收节点，不能藏在“完成开发”里。
4. 逐条把 PRD 验收项映射到工作包和任务；核对原型页面/交互、权限、失败/边界路径及架构约束。无法映射或信息冲突时标为待裁决，不自行发明需求。
5. 按依赖排序，先执行可验证的任务；高风险决定给用户，范围内的常规实现继续。
