# 新项目接入完整开发流程使用教程

适用方式：项目内放轻量入口，共享目录保留完整流程，AI 按当前任务需要读取资料。

## 一、先理解两个目录

- **业务项目目录**：例如 `E:\我的项目\订单系统`。保存这个项目的代码、需求、计划、任务、进度和验证摘要；证据工具的原始日志与 receipt 使用项目专属外置目录。
- **共享流程目录**：`E:\自动化开发任务通用流程\自动化开发全流程`。保存通用规则、模板及校验工具，业务开发时只读使用。

`starter-project` 可以独立作为基础模板使用，但模板已预置共享路径与只读边界，状态仍是“待接入”，复制后需完成首次核验和启用。本教程采用“模板 + 显式连接完整流程”的用法。

完成下面三步，就完成了流程接入。接入不代表已经完成开发，也不代表所有工具、模型或外部执行器都已可用；实际使用前仍须检查相应能力。当前没有无人值守调度器，关键人工确认仍需由你完成。

## 二、首次使用：依次完成这三步

### 第 1 步：复制模板内容到新项目

打开模板目录：

```text
E:\自动化开发任务通用流程\自动化开发全流程\ai-development-workflow-v1\starter-project
```

把这个目录**里面的全部内容**复制到你的业务项目根目录，包括 `.ai-dev`，不要再套一层 `starter-project`。

例如复制后：

```text
E:\我的项目\订单系统\
├── AGENTS.md
├── .ai-dev\
├── docs\
└── 其他模板文件及你的项目文件……
```

如果看不到 `.ai-dev`，检查文件管理器的隐藏项目显示设置。已有项目只合并需要的内容，同名文件先核对，保留现有规则、代码和计划，不直接覆盖。不要把共享目录中的 `.venv`、`.uads`、UADS 源码和测试一并复制过来。

### 第 2 步：用 Codex 打开业务项目目录

例如打开 `E:\我的项目\订单系统`，在这个项目下新建任务。确认当前工作目录是业务项目目录，然后提供已有需求、PRD、原型、架构等文件的位置；已完成并批准的资料可以继续沿用。

### 第 3 步：发送首次接入提示词

下面就是**第一次与 AI 对话时使用的完整提示词**。先完成复制和打开项目，再原样发送；共享目录搬迁后需替换其中的路径。

```text
请为当前业务项目接入共享的完整开发流程。

共享流程根目录：
E:\自动化开发任务通用流程\自动化开发全流程

完整规则包目录：
E:\自动化开发任务通用流程\自动化开发全流程\ai-development-workflow-v1

请完成以下工作：
1. 确认当前工作目录是业务项目，先阅读本项目 AGENTS.md，检查现有资料和已有修改。
2. 检查共享目录能否读取。核对规则包 WORKFLOW_MANIFEST.yaml 中的实际版本，阅读 PROJECT_EXECUTION_RULES.md、policies/CONTEXT_POLICY.md 和 policies/SHARED_LIBRARY_USAGE.md；其他资料只按当前任务需要读取。
3. 更新本项目 AGENTS.md 已有共享接入节：记录共享路径、Manifest/契约版本、实际 Git HEAD 与 dirty 状态、权限核验结果及项目专属证据目录。核验接入所需条件后标记“明确启用”；条件缺失则保留待接入并说明。共享库有未提交内容时，对实际使用文件保存相对路径与 SHA-256 基线到项目已有记录，不把 HEAD 当成当前全部内容的版本。保留现有项目约定，不复制完整策略正文，不建立第二套重复规则。
4. 写明加载约定：每个任务先读本项目入口、当前任务和直接相关文件；根据 CONTEXT_POLICY.md 选择需要的规则，不批量读取全部 docs、policies、templates 或历史日志。同一会话中未改变的文件不反复加载。
5. 核对写入边界：代码、文档、状态及 Request/Result 写当前业务项目；原始日志、receipt 和报告写本项目专属证据目录，该目录必须在代码工作区和共享库之外，并按项目/task/attempt 隔离。记录实际绝对路径，核对链接目标，不能与其他项目混用。运行共享工具时从业务工作区调用工具绝对路径，核对真实参数。共享 Python 禁写字节码缓存，其他子进程缓存另行检查。不能因为目录可读就宣称模型、执行器或机器门禁已经可用。
6. 查看当前执行环境的实际权限：业务工作区及本项目专属证据目录需要必要写权限，共享库不得在可写范围或其可写父路径下；业务任务不向共享库提权写入、不安装共享依赖、不更新共享配置。不能确认硬隔离时记录“仅规则约束，硬隔离未验证”，不做试写共享库的验证；权限不足不改用共享目录保存输出。
7. 后续会话以本项目 AGENTS.md 为入口。核对版本及相关文件摘要变化，说明/链接等低影响修订核对后直接更新记录；影响审批、权限、费用、执行或验收的变化按影响确认。共享路径失效或能力缺失时报告，停止依赖步骤，不静默降级或虚报通过。版本记录不等于冻结旧版。
8. 检查已有需求、PRD、原型和架构，判断项目当前阶段，列出必要缺口及下一步。复用已经批准的成果，不从头重复全部前期工作。需要架构确认或其他人工验收时，先完成可供我审阅的结果，再到约定节点停下。

本轮只完成流程接入、必要的项目规则记录和现状检查，不编写业务代码，不修改共享流程库。
完成后告诉我：更新了哪个文件、记录的路径和版本、实际检查结果、仍未验证的能力，以及下一步我应发送什么指令。
```

这一轮完成后，查看 AI 是否确实更新了**业务项目的** `AGENTS.md`，是否记录了正确的路径和版本，以及有没有报告无法访问或工具缺失。仅回复“已理解”不等于完成接入。

## 三、接入以后怎样开始开发

首次接入提示词要求本轮不写业务代码，因此接入后需要根据项目现状发出下一条任务指令。

### 情况 A：已有需求、PRD 和原型，需要开始架构设计

替换资料位置后发送：

```text
流程已经接入。需求、PRD 和原型分别位于：〔填写实际文件路径〕。
请核对这些资料，复用已批准的内容，按本项目启用的流程开始架构设计。
说明系统模块、数据与接口边界、关键技术选择、基础设施验证方式和验收标准。
先提交可审阅的架构方案，等我明确确认后再进入实现。
```

### 情况 B：架构和计划已经确认，开始一个工作包

只有在你确实确认过对应方案后，才使用这段：

```text
我已确认〔填写架构文档和工作包计划的位置〕。
请按已确认范围执行〔填写工作包名称〕，完成实现、相关测试、必要修复、规定的审查和集成验证。
保留现有修改，按需读取共享规则；普通执行步骤不重复请求确认。
遇到约定的人工验收点、超出授权范围的重大变化或无法满足的门禁时，保存现场并说明情况。
完成后更新项目现有进度记录，提交实际验证证据及未验证事项。
```

### 情况 C：需求还不完整

直接说明想做什么、面向谁、主要功能和已有资料，让 AI 先判断缺少哪些影响实施的信息。不要为了填满模板而编造需求或批准记录。

## 四、开发过程中如何使用

| 当前阶段 | 你做什么 | AI 按规则做什么 |
|---|---|---|
| 资料检查 | 提供目标和现有资料 | 核对当前阶段，补必要缺口 |
| 架构设计 | 审阅并明确确认方案 | 形成可审阅架构与验收方式 |
| 开发准备 | 完成约定的基础设施验收 | 验证环境，按规模组织阶段、工作包和任务 |
| 开发执行 | 授权具体任务或工作包 | 在范围内持续实现、测试和修复 |
| 审查与集成 | 处理需要人工决定的问题 | 按对应门禁审查、集成并记录实际证据 |
| 阶段交付 | 在约定检查点验收 | 对照批准需求，说明完成项和未验证项 |

小任务按相称规模执行，不要求每次都重走整个项目生命周期。一个已授权工作包内的普通步骤可以连续推进，但不会跳过明确规定的人工检查点。单个任务测试通过不等于整个项目验收通过。

## 五、换窗口或隔天继续

在 Codex 中打开同一个业务项目，新建任务后发送：

```text
请从本项目 AGENTS.md 开始，核对启用的共享流程及按需加载约定。
读取与恢复有关的现有进度或检查点，检查当前文件和 Git 状态，区分历史测试记录与当前核验结果。
先简短说明当前阶段、已批准范围和下一步，然后继续执行已授权且尚未完成的工作。
不要仅凭旧会话结论宣称验证通过；遇到尚未批准的阶段或人工检查点时，停在对应边界。
```

不需要每次粘贴完整规则。项目入口保存共享资料的位置；项目进度和检查点保存已经做到哪里。AI 需要能够读取这些文件，才能可靠恢复。

## 六、常见疑问

### 只复制 starter-project 就会自动读取共享目录吗？

模板已预置共享路径，但状态为“待接入”。第 3 步核对路径、版本、输出位置和实际权限，再记录启用状态。完成后，后续 AI 按入口约定按需查阅。

### “自动读取”是什么意思？

是 AI 在处理任务时遵循项目规则主动查阅对应文件，不是文件系统自动加载，也不是后台程序自行运行。路径可访问、读取权限和执行器能力仍是前提。

### 会把所有文件都放进上下文吗？

约定是按任务读取：入口和当前任务优先，再根据索引读取相关段落。详细日志和历史资料留在磁盘，只有调查或审查需要时读取。这样减少无关上下文，但不保证固定的 token 数或费用。

### 每个新项目都要重复三步吗？

每个项目首次接入做一次。已经接入的项目日常直接提出任务；换窗口按第五节恢复。不要反复覆盖模板或重建已有计划。

### 共享目录换了位置或换电脑怎么办？

先让共享目录在新位置可访问，再更新各业务项目入口记录的路径并核对版本。无法读取时应明确报告，不能假装仍在执行完整流程。

### 是否能从头到尾完全不用我参与？

当前不能。已授权范围可以持续执行，但架构确认、约定的人工验收和超出范围的重大决定仍需你参与。当前方案未实现无人值守调度。

## 七、多项目使用与权限

- 项目 A、B 共用规则，但各有 AGENTS.md、任务、状态和结果；例如 A 的证据放 `E:\项目证据\A-唯一标识`，B 放 `E:\项目证据\B-唯一标识`，各自按 task/attempt 分开。
- 业务开发打开业务目录，共享库只读；维护流程才单独打开共享库，并明确授权修改范围。不要在业务任务中自动更新共享规则、依赖或模型绑定。
- 首次接入让 AI 查看实际权限配置：共享库不能被额外可写目录或可写父目录覆盖，项目证据目录需具备必要写权限。模板本身不会设置 Codex 权限；无法核实时必须说明，不能把“文件夹只读属性”当硬隔离。
- 当前工具不是全局写入沙箱。输出参数核对、子进程边界与实际执行环境的权限都需生效，才能对误写形成硬保护；不能声称只复制模板就自动具备这种保护。
- 共享规则未提交时，版本号和 HEAD 不足以识别实际内容，因此只对采用的文件记录摘要，不加载全部文件。版本记录用于发现变化；不同项目必须固定不同版本时，另行采用独立发布目录。
- 已经复制过旧模板的项目不会自动更新：只合并新的共享接入节，再运行本教程的首次接入提示词，保留原有业务规则和记录。
