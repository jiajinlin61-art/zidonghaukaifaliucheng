# 最小执行规则

适用于明确启用完整规则包的业务项目。用户明确指令和适用项目约束优先。

1. 首次只读本文件、当前 Task/需求及相关代码；按 [上下文索引](policies/CONTEXT_POLICY.md) 触发补读，不递归加载文档。
2. 新功能或实质性范围变化先展示相称的计划并获得明确确认，包括 FAST；FULL 再确认设计基线。已有批准范围内连续实现、修复和验证，不按 Task 重复请示。审批细节仅在触发时读 PROJECT_START_GATE 策略。
3. 当前 Task 写清目标、非目标、允许路径、验收和停止条件；保留用户已有修改，每次开始与集成时核对目标。delegated_worker 不修改项目 NEXT/DONE。
4. 完整流程执行前必须实际 Router/Preflight；Worker 与已解析 route 一致。Controller 直接实现必须具有契约中的显式 override，不静默替代 Worker。模型绑定不在项目任务中重定义。
5. 完整流程使用 Execution Contract 1.4；命令由证据工具采集。每个连贯变更运行相关检查，失败后复验失败项及受影响路径；全量/端到端检查放在集成时运行。
6. 独立 Reviewer 使用不同会话或真实人工审查；模型 Reviewer 与 resolved_review 一致。审查绑定具体内容及 Git 提交，之后修改内容/提交须重新验证审查。成功声明不能代替证据。
7. actual 契约校验必须通过才返回成功；模板/纯结构校验不是实际通过。项目级 DONE 由 Controller 在集成和用户目标核对后决定。
8. 默认最多首次执行加两次重试；保留稳定失败指纹，换模型/会话不重置计数。只有发生失败时读重试策略。
9. 未决人工问题、失败计数和下一动作在中断/关键变化时保存；恢复需核对当前工作区，历史会话不是事实来源。
10. 尚未授权的破坏性、对外发送/发布、付费、权限/凭据变更及实质业务取舍需用户决定；已有授权不重复询问。
11. 技能按任务实际需要加载，显式调用优先；Ponytail 仅显式调用。新建前后端项目使用 frontend/ 与 backend/ 分离目录并明确 API 契约；已有项目沿用已批准的边界，不以模板为由搬迁已有项目。
12. Stage/Phase 记录有用经验；FAST 仅在有可复用经验时在结果加一句，不创建额外回顾文件。交接传递目标、契约、路径、工作区事实、验证、失败历史和下一动作，引用原证据而不复制日志。
