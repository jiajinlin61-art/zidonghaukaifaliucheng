# 多项目共享流程使用边界

仅首次接入、权限/路径/版本变化或工具写入排错时读本文件。它不自动创建权限或调度器；日常从项目 AGENTS.md 和当前任务进入。

## 路径与写入归属

- 共享根保存通用规则、模板和工具；业务项目不能嵌套在共享根内。项目间不共用 CURRENT_STATE、CHECKPOINT、Request/Result、日志或模型会话。
- 项目根保存业务代码、计划、状态和 Request/Result。原始 receipt、stdout/stderr、snapshot 及审查报告按当前工具要求放在代码工作区外。
- 每个项目明确一个专属证据根，例如代码 `E:\我的项目\订单系统` 对应 `E:\项目证据\订单系统-唯一项目标识`，下分 task/attempt。示例路径不会自动创建；同名项目必须使用不同标识，迁移项目时同时迁移证据并更新引用。
- 接入记录写在项目 AGENTS.md 的共享节：状态、共享根、Manifest/契约版本、Git HEAD/dirty、专属证据绝对路径和权限核验结果。不要另建重复的配置系统。
- 写入前解析绝对路径和符号链接/目录联接目标；共享目录及其父路径、其他项目目录不能作为项目输出根。不能把共享目录通过链接接入可写项目后绕过只读约定。

## 权限与维护模式

1. 业务开发以业务项目为工作目录；执行环境仅开放该工作区、该项目专属证据根及必要临时目录的写权限。共享库保持可读但不在可写范围，不能使用不受限执行来绕开边界。
2. 接入时查看执行环境实际提供的权限信息，不通过试写共享文件来证明只读。若共享库被父目录可写授权覆盖，应缩小授权或使用能提供隔离的环境；无法确认时记录“仅规则约束，硬隔离未验证”，需要硬隔离的执行步骤先停下。
3. 模板和提示词不能替平台设置权限。证据目录在工作区外时，须在实际运行环境中开放该项目证据目录的必要写权限；权限不足不改写到共享库。不要用 Windows 文件夹属性的“只读”勾选冒充安全权限。
4. 子进程、外部 Agent 和工具宿主必须核对自己的权限，不能假定继承主控的全部限制。工具路径检查不是操作系统沙箱。
5. 共享库的依赖修复、通用规则/模型配置修改在专门的维护任务中处理，由用户授权相应范围。业务任务中不自行提权写库；改进建议先保存在业务项目。

## 工具调用与写入清单

业务执行从代码工作区调用工具的绝对路径，Request/Result/证据参数也使用绝对路径。先检查工具真实支持的参数，不能编造通用 --output 参数。

| 工具 | 输入及运行行为 | 写入归属 |
|---|---|---|
| model_router.py | --config 读取绑定，路由结果输出 stdout | 若重定向，只写项目文件 |
| route_preflight.py | --config 读取绑定，读取本机配置并运行执行器版本命令；不是新的远程模型探测 | 主脚本输出 stdout；外部执行器的缓存另行核对 |
| delivery_evidence.py | --workspace 指向代码工作区；--evidence-root 指向项目专属外置证据目录；执行指定子进程 | 日志、快照、receipt 写 evidence-root；子进程可能写业务代码，其额外输出另行限制 |
| evidence_result_update.py | --request/--result 为本项目文件，--evidence-root 同上；工作区来自 Request | 原子替换 --result，临时文件在 Result 同目录；报告记录写 evidence-root |
| execution_contract_validate.py / project_acceptance_validate.py | 读取当前项目契约/验收映射和证据；检查工作区/Git | 主脚本输出 stdout，重定向只写项目目录 |

共享 Python 使用已核验且依赖可用的解释器，不在业务开发中修改共享 .venv。调用加 `-B`，并在该次执行环境设置 `PYTHONDONTWRITEBYTECODE=1` 供 Python 子进程继承；其他工具缓存按各自参数定向到项目/临时目录。若工具必须写共享库或依赖缺失，报告并停止依赖步骤，不能自动安装或切换为无隔离执行。

证据工具会拒绝 evidence-root 在代码工作区内，但目前不会统一拦截所有共享库/其他项目输出路径；Result 更新器按传入路径写入。以上规则必须与实际权限配合，不宣称已有全局防误写拦截。示例和实际参数见 [证据操作说明](DELIVERY_EVIDENCE.md)。

## 版本核对与更新

- 首次接入记录 WORKFLOW_MANIFEST.yaml 的 version 和 execution_contract_version。Git 可用时记录实际仓库 HEAD 及共享库范围的未提交/未跟踪状态；Git 不可用时明确记录无提交基线。
- 未提交改动可能不改变 Manifest 版本或 HEAD。对实际采用的规则/工具保存相对路径和 SHA-256 到项目已有接入/任务记录，不递归读取整个库。新会话及文件重新使用时核对对应摘要；同会话未变化的资料不反复加载。
- 摘要变化后比较相关内容：说明/链接修正等不影响执行的变化核对后更新记录；影响批准范围、权限、模型费用、执行方式或验收标准的变化，先明确影响并保留必要人工决定。证据缺失时不能宣称变更无影响。
- 版本基线仅用于发现变化，不提供不可变快照。记录与当前内容不一致时，不能声称仍在运行旧版。确需不同项目长期固定不同版本时，再维护独立、已确认的发布目录；不在业务任务中回滚共享库。
